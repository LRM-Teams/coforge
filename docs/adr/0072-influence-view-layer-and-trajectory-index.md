# Influence View 层定位为派生轨迹索引：post-run 生成经济性、混合检索与 grounding 双向可达

在权威事实层（L0 AO 台账 / L1 Segment+Interaction DAG）与长期因果记忆（L3 Fork）之间建立 L2 Influence View 层（Q95/Q102 重定案）。定位重述（Q121-A/M3，经双重独立评审否决 L2/L3 合并）：**post_run_index 视图是 AO 台账的派生轨迹索引，DIV 是诊断工作集；系统只有一层长期因果记忆（L3）**。视图分两种 purpose：轨迹 commit 后异步生成 `purpose=post_run_index` query-neutral 基础视图（覆盖成功/失败轨迹）；失败诊断以其 + 失败 outcome + diagnosis query 派生 `purpose=failure_diagnosis` revision。二者共享 InfluenceBlock/InfluenceClaim/grounding schema，后者可复用或 supersede 前者。不合并进 L3 的理由：fork:anchor 是 1:1 跨任务稳定身份而 fork↔view 是 M:N；Q99 三层信任分离（schema validity / semantic plausibility / evidence verification）不允许导航级信任冒充证据级；可见性矩阵、生命周期频率（每轨迹 vs 按需稀疏）与检索排序特征均不同源。

**覆盖与生成经济性**：post_run 视图采用有界目的性覆盖（Q109-A）——以"task 目标 + observed outcome"为组织 query，覆盖任务执行路径相关子集，必须带 coverage_manifest（omitted ranges 与理由、snapshot watermark），沿用 Q97 结构约束（无环、虚拟 root→observed-outcome sink 弱连通、跨 omitted range 显式 skip）；不做全轨迹重写、不做固定窗口。生成由独立服务端异步索引服务承担（Q110-A，与 outbox/aggregator 同模式）：workspace 级预算与速率上限，队列优先级 evaluation > 失败轨迹 > 成功轨迹；预算耗尽/超限降级为 deterministic fallback view 或明确无 projection；supersede 的旧 revision 与 projection 退出索引只留审计；workspace 可暂停。多 commit 会话按 session/task run 演化（Q111-A）：后续 commit 的构建产生 superseding revision，旧 revision 保留为历史证据（诊断可引用）但 projection 退出检索——避免重叠视图瓜分配额、半成品轨迹冒充完整经验，同时保证中途崩溃的 session 至少留有最后一次 commit 的索引。

**混合检索与投影治理**：三 corpus（Fork/Branch、冻结 Block/Claim projection、当前 Segment/Atom）采用分层配额（Q112-A）——Interaction lane 维持独立候选预算不占 12；causal-memory lane 内 12 为查询级总帽，默认 Fork/Branch 6、Block/Claim projection 4、Segment/Atom 引用展开 2，role profile 可调但总帽不变；verified/provisional 8-4 通道切分只对有状态语义的对象生效。接口层统一（M1）：单一检索响应信封（kind、来源通道、通道内 rank、状态标签、来源指针）+ 单份 ranker feature spec，存储与 ranker 仍按 corpus 分开。投影通道跟随 grounding 状态（Q113-A）：被 validated ForkRevision grounding 的 block/claim projection 可进 verified 通道并带 provenance 标签，其余保持 provisional；投影命中只记索引级 exposure、不进 citation/utility/fork 聚合（M4' 记账隔离详见 ADR-0075）。投影继承来源 AO/Segment 安全标签（Q114-A）：ACL 变更事件经 outbox 触发再投影/撤下（redact 或退出索引），引用它的 Fork grounding 标 needs_revalidation——防已发布摘要卡片构成侧信道。检索查询支持"子目标 + 依赖模式"（Q122-A）：以想要的 artifact/effect 匹配 Claim 的 carried_artifact/downstream_effect 签名，命中后只在同一冻结视图内沿 Claim 做有界邻域展开（读时拼装"子任务因果链"、不落成对象）；不铸造 subtask_id，跨任务命中仍按 task_id 记 cross-task。

**grounding 双向可达**：正向已有——每个 ForkRevision 的 `influence_grounding` 指向冻结视图 `block|edge|cut`，并附带内容寻址快照（view revision id + 位置 + 语义摘要 + content hash，M2），消费 fork 免跨层 join；视图 supersede 或 ACL 变化走 needs_revalidation 联动，不改写已提交 revision。反向新建（Q123-A）：对已是 grounding 目标的位置维护倒排索引（outbox 投影层派生、可重建），READ_VERIFY 阶段可读对应 Fork/Branch 轻量摘要与该分支验证状态，单独标"干预史"——不改变 Claim 状态、不把 Branch 写成图出边（干预语义 ≠ 观察归因语义）、不进 citation/utility。反向读取必须逐条过 ACL；看到"此处有 validated 分叉"不等于"该影响边被支持"。
