# 5. 让组件承担重复决策

- 优先使用现有 Button、Dialog、Tooltip、Select 等原语。只有真实重复需求才沉淀共享模式，不为单个页面新建一套设计系统。
- 使用语义颜色。主按钮与品牌强调按既有规范区分；状态颜色同时有文字或其他非颜色线索。
- 同级元素使用一致的字号角色、间距和对齐。不要因为一段文字长就单独缩小它，也不要用极小浅灰字掩盖信息过多。
- 每个间距由一个布局容器负责，避免父子叠加 margin。留白服务于分组与重点，不留下无意义的大块空区。
- 表格和代码等内容获得足够空间，不因旁边一段说明被挤成窄栏。先重排，再考虑局部滚动；不能隐藏页面溢出来掩盖问题。
- 卡片、边框和底色须表达真实分组、选择或交互范围。避免卡片套卡片、普通元信息全部变成胶囊、每个标题都配图标与小标签。
- 动效仅用于反馈和状态连续性，尊重减少动态效果偏好，不给静态信息增加循环闪烁、逐段入场或模拟打字。
- 克制不是纯黑白模板，也不是禁止一切装饰。保留有依据的品牌表达，让主内容比辅助元素更突出。

## 加载与反馈样板

工作台覆盖聊天、Agent 列表和详情、Computer 列表和详情、设置首屏与个人资料保存。
创建和编辑 Agent、运行时凭据、Computer 运行时可见性使用就地错误与防重复提交。
参考 Linear 的稳定层级、Geist 的尺寸占位、Sonner 的连续反馈；保留 CoForge
品牌色和 Untitled UI 官方组件，Toast 使用 Sonner。以下时间与布局是样板的工程默认值，
不是 Figma 已发布的品牌标准，也不是对参考产品参数的复刻。

| 场景 | 呈现方式 |
| --- | --- |
| 首次进入消息页、Agent 列表 | 保留可展示的结构和静态标签，未知内容显示骨架；空状态只在读取完成且确实无数据时显示（消息流的判空由 stream 状态机守住，读取未结算不称空，避免骨架与空状态闪换） |
| 切换私聊或频道 | 会话列表保持可用，目标内容区局部加载；不能在新目标下显示上一会话的消息或发送入口 |
| 已有列表刷新 | 保留真实内容、筛选值与输入元素，不重新显示骨架 |
| 会话加载失败 | 消息区域内说明失败并提供重试；保留会话列表和窄屏返回入口 |
| 个人资料保存 | 按钮显示保存中并阻止重复提交；成功在资料区简短确认，失败保留编辑内容并就地说明 |
| 短暂、非关键操作结果 | 共享 Toast；已有就地反馈时不再重复弹出 |

推广时保留已有的空列表、无搜索结果、Computer 未找到、频道加入、消息发送失败与重试界面；
不把这些确定状态换成骨架。安装指引、登录授权和立即发出的 Agent 控制命令不是页面数据加载，
保持各自的流程反馈。设置通知和时区的保存失败按[第 13 节](toast-vs-inline.md)在对应设置项旁就地说明原因（现有实现仍用 Toast，属于待改存量）。

- pending 骨架的策略只写一处：路由器默认值（`apps/web/src/lib/pending-policy.ts`，`defaultPendingMs` /
  `defaultPendingMinMs`），路由不再各自复述这两个数字。延迟内不显示骨架（快速请求不闪屏）；一旦到达延迟线，
  骨架至少停留同样长的时间 —— 否则它会"闪一下"就消失，看起来像故障而不是加载（#112/#113 的通道打开就是这个）。
  各路由只声明自己的 `pendingComponent`。此策略不承诺在 JS 或认证信息尚未加载时渲染完整工作台。
- 骨架沿用最终布局的间距、列数与容器尺寸；只提示头像、文字、列表等主要轮廓，
  不伪造状态点、未读数或运行进度。使用中性 Token 与轻微同步明暗变化，减少动态效果时静止。
- 骨架装饰从可访问树隐藏，区域标记 `aria-busy`，一组内容只发出一次加载提示。
  加载文案仅供屏幕阅读器读取，不在骨架上重复显示 Loading；保留标题区和真实返回入口。
  不让不可用的占位控件进入键盘操作顺序。
- 头像和资料不是原子事务。头像成功、文字失败时明确说明部分成功，保留文字，
  重试不重复已完成的头像操作；未经服务端确认不能声称回滚或全部保存成功。
- Toast 在桌面位于右下角，手机（小于 768px）位于顶部居中，留出安全区；最多同时显示三条，同类型、同标题更新原条目。
  使用中性浮层、细边框、图标与简短文案，避免大面积红绿底色。正文错误色使用
  `text-error-primary` 而非填充色。使用 Sonner 默认四秒自动消失、不显示关闭按钮，保留原生堆叠、展开与减少动画支持。
  `AppToastProvider` 统一 Toaster 配置，`useAppToast` 仅负责去重，不携带错误编号（错误编号按[第 13 节](toast-vs-inline.md)只出现在内联失败说明下方），不自行实现通知队列。
- Toast 不自动抢焦点。配置 F6 进入通知区；交互期间的暂停计时由 Sonner 负责。
  Escape 折叠通知堆叠，不承诺恢复到触发前控件；通知采用 Sonner 的礼貌播报。
  必须处理的错误、断线状态、消息发送失败和字段校验不能只存在于短暂 Toast。
- 通用页面还应区分无数据、无搜索结果、无权限、失败与刷新，不用一个空状态覆盖它们。
  加载、消息已接受、Agent 在线与 Agent 活动是不同事实，不互相推断。
- 浏览器推送订阅会静默失效：权限回收、浏览器清理订阅、服务端密钥轮换后的不匹配都发生在用户看不到的地方。
  设置页通过 `browser-push-lifecycle` 在加载时按需重新注册，不弹通知打扰；「发送测试通知」区分
  「还没有可用的订阅」与「发送失败」，各自给出可行动的提示，不让一次零送达静默通过。
- 频道线程头部的 Following Agents 用头像触发器表示：不在标题里罗列 @handle；触发器是最多 3 个
  叠放头像加关注数量，无人关注时不显示，数量同时放在 aria-label 里。
  详情收进按需弹层（头像 + 名字 + 移除，分行排列）；弹层里的按钮用小尺寸，行间用分隔线，
  不堆叠常驻占位。
- 输入框内的候选（提及等）同时支持键盘与指针：指针在 pointerup 提交，不对 touch `preventDefault`——
  Safari 在被阻止的 pointerdown 后不触发 click，且会让输入框丢焦点（键盘闪烁、输入中断）。
  同一手势只提交一次；候选列表遵循 WAI-ARIA 的归属结构，`option` 直接被 `listbox` 拥有，
  中间的列表元素声明 `role="presentation"`，键盘与读屏路径保持一致。
  候选弹层与输入框同宽，每个候选一行：头像、名字、Human/Agent 徽章、简介，`@handle` 以 `text-xs`
  靠右并在过长时截断。行高 36px（粗指针 44px），是列表行高 40 到 48px 的例外：弹层只占输入框
  上方一小块，单行更紧凑才能露出更多候选。
- 按钮里的图标必须一眼可读。读作「空白占位」的图形（如 UntitledUI 的 `Stop`，是一个空心方框）
  不上按钮：宁可不配图标，也不要让实心主按钮上出现一个像渲染失败的方框。
