# 5.1 空状态复用组件，但不混淆业务状态

空状态是内容尚未出现时的任务入口，不是放在页面中央的通用占位提示。使用了 `Empty` 不代表完成设计；统一的是层级和操作原则，不是让聊天、电脑、成员和搜索结果都长成同一张“小图标＋No data”模板。

## 先按场景决定内容

| 场景                     | 应表达什么                             | 视觉与操作方向                                                                                                  |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 首次使用、尚无对象       | 这里将出现什么，以及如何添加第一个对象 | 可使用对象主题的轻量插画；提供一个明确的主要操作，例如连接电脑或邀请成员。                                      |
| 已选中 Agent，但尚无消息 | 正在与谁交流，以及消息从哪里开始       | 优先使用当前 Agent 的真实头像／已有头像回退和名字，配一句简短提示；保留现有输入框，不增加重复的“开始聊天”按钮。 |
| 已选中频道，但尚无消息   | 当前频道及其交流上下文                 | 使用频道标识与名称，引导发送第一条消息；不要伪造成员头像或已有活动。                                            |
| 尚未选择对象             | 需要先从列表选择对象                   | 用轻量选择提示，不暗示已选对象没有数据；不改变手机列表优先的导航规则。                                          |
| 搜索或筛选无结果         | 当前条件没有匹配项，而非系统没有数据   | 保留搜索／筛选控件，使用小图形和短提示；提供清除筛选或修改搜索的恢复路径。                                      |
| 局部区域暂无内容         | 该区域尚无回复、记录等内容             | 使用紧凑图标和短说明，不用整页插画挤走根消息、相邻内容或输入区。                                                |

正在加载、加载失败和无权限不是“尚无数据”。不要仅凭空数组选择空状态，也不能把这些状态显示成“No messages yet”。有数据后恢复正常内容，空状态与非空内容不能同时占据同一区域。

Members 同时展示 Workspace 的真人和 Agent，当前用户也属于成员。页头用「智能体 (N)／协作者 (N)」两个 Tab 分开两类成员，数字是该类总数，不随搜索和筛选变化；默认智能体，Tab 保存在 URL，刷新和浏览器返回保留选择，切换 Tab 保留搜索内容。页头右侧的主要操作跟随 Tab：智能体 Tab 是「新建智能体」，协作者 Tab 是「邀请」，均只对有权限的人显示；不显示「连接电脑」，只有发起创建且没有可用电脑时，才在创建弹窗中解释前置条件并提供连接入口。智能体 Tab 提供「我的／全部」（按创建人）与「电脑」筛选，两者保存在 URL；搜索覆盖当前 Tab 的人员、Agent 名称和 Agent 电脑名称，搜索词不进 URL。使用独立的圆角成员卡片，手机单列、桌面按可用宽度排列多列，不使用横向分割线列表。Agent 卡片依次展示头像与在线状态、名称与所属电脑（未分配时如实说明）、`@用户名`、两行简介，底部是创建人与创建日期（按查看者设置的时区和界面语言格式化；未设置时区时按浏览器时区）；协作者卡片只展示身份与简介，不放电脑、运行时或在线状态占位。目录不展示成功率、费用、时长等运行统计。成员卡片分页加载：首屏一页，向下滚动接近底部时自动加载下一页（React Aria `GridList` 的 `GridListLoadMoreItem`），筛选和搜索在服务端完成并从第一页重新加载，加载新条件期间保留当前卡片；卡片网格用方向键在卡片间移动，Tab 进入卡片内的私聊按钮、菜单和名称链接；下一页加载失败时在列表末尾就地显示原因和重试。筛选或搜索没有结果时使用成员搜索空状态并提供清除搜索和筛选的操作。目录仅保留有权限的私聊、Agent 详情与删除入口，重启和运行配置留在详情页。没有 Agent 或电脑不等于没有成员，不能用连接电脑的整页引导遮住已有人员。

Members 的 Agent 卡片右上角是文字按钮「私聊」和一个有可访问名称的更多操作菜单（查看详情；Workspace owner/admin 另有删除，走与详情面板相同的确认对话框）；在线状态仅用头像旁的小绿点，离线沿用灰点，不重复显示状态文字。Human 与未取得状态的 Agent 不伪造在线标记。

## 图形、文字和操作形成一个紧凑的内容组

- 图形须对应当前对象或任务：头像用于交流对象／成员，小图标用于局部提示，轻量插画用于需要引导的首次使用。不要所有页面都套同一个灰色圆角图标底座，也不要为了装饰堆叠无业务含义的头像。
- 插画只承担辅助表达，采用与页面协调的中性色、少量层次和既有品牌强调；不添加突兀色块、大幅营销插画或循环动效。参考外部组件的构图，不直接搬入另一套主题；复用素材前确认授权与来源。
- 层级依次为图形、简短标题、必要说明、可用操作。标题说清当前对象或状态，说明补充原因或下一步，不重复标题，也不使用玩笑、口号或责备式文案。
- 标题和说明使用自然字距与行距。控制文本宽度，让中文和英文都自然换行；不要两端对齐、逐词撑开，或为塞下文案单独缩小字号。
- 默认只强调一个能推进任务的主要操作；次要操作只有承担不同且必要的任务才出现。按钮必须符合用户权限和实际能力。页面头部已有相同入口时，明确空状态内外的主次，不让两个同权重按钮竞争；已有输入框时直接利用输入框。

## 布局适应容器和手机，而不是机械居中

- 图形、标题、说明与操作之间的距离，应让它们被看作一组；周围留白用于突出这组内容，不靠把元素拉散来填满页面。
- 整页首次使用可以有较完整的视觉；列表、侧栏、线程等局部空状态使用较小尺寸。不要把整页方案原样缩进小容器。
- 手机端保留页面头部和必要输入／操作区，在剩余内容区安排空状态；高屏上可适当偏上，不要求垂直正中。短屏、键盘展开或长文案时允许内容滚动，不能遮挡或推出主要操作。
- 明暗主题都保持图形与背景融合、文字和控件对比清晰，不把白底插画贴到深色页面上。装饰性图形对辅助技术隐藏，标题和说明使用正确语义；真实按钮、链接保留可访问名称与键盘操作。

## 实现与验收

- 复用 [Empty 组件](../../apps/web/src/components/ui/empty.tsx)：`Empty` → `EmptyHeader` → `EmptyMedia`、`EmptyTitle`、`EmptyDescription`，需要操作时使用 `EmptyContent`。`EmptyMedia` 可以承载图标、头像或合适的插画，不限于 `variant="icon"`。
- 展示原语负责结构，功能模块负责业务状态、真实对象、本地化文案与操作。优先使用现有头像、图标和语义颜色，不为一个空状态安装另一套组件库。
- 评审必须把空状态放回真实页面，检查手机／桌面、长短屏、中英文和明暗主题：能否辨认当前上下文，文字是否自然，主要操作是否可达，是否有过大留白或重复按钮。状态切换还须确认加载／错误不会误报为空，数据出现后空状态消失。
- [参考](references.md)中的组件库链接用于视觉参考，不是要求照搬，也不表示现有页面已达到这些原则。后续新增或修改空状态时按本节执行。
