  1. Workspace 选一个 profile，不按问题分流。desired 取值是 off | openviking | causal_openviking。两个启用中的 profile 都保留完整 OpenViking 能力；因果 profile 额外打开 Causal Memory。

Chapter III · non-normative · 规范在 docs/architecture.md §15

Workspace profiles：完整 OpenViking，可选 Causal Memory

Workspace 选一个 profile。两个启用中的 profile 都保留完整 OpenViking。因果 profile 把 OpenViking 当成内部 Fact Index 适配器，而不是对等记忆真源。没有自然语言路由器。

3.1 · 海马体图 vs Viking 记忆

同一份课，两套完全不同的几何

第一章的测试图是有向带权图：节点是文本块，边带着 caused / prevented 和预乘系数，查询靠激活扩散。Viking 的记忆是带摘要的目录树：节点是文件，边是父子路径（外加可选 wiki 链接），查询靠 URI + 向量命中 L0。几何不同，所以因果 profile 只能投影，不能用自然语言在两套真源之间选。下面用同一组「mutex / channel」课对照。

3.2 · 原则

Workspace profile 挡住错误的合并和错误的分流

上一节只说明几何不同。规范选择是：Workspace 选 profile，因果内部用 Fact Index 投影。不按问句把流量分给两套对等真源。

P1

一个 Workspace，一个 profile

desired 是 off | openviking | causal_openviking。不按 Agent、不按 query 切换。两个启用中的 profile 都保留完整 OpenViking backend 能力。

P2

一个 admitted 段，一个抽取器

自动团队记忆只接纳已完成 Task 窗口和 PublicChannel quiet window。DirectConversation 永远排除。同一段不得同时进 OpenViking 原生抽取和 Causal distill。

P3

写域分开

普通文档、导入资源、个人 session、skill 留在 OpenViking 原生写域。只有 admitted 团队记忆在因果 profile 下进入 Causal Memory。

P4

Canonical 在 Causal Memory

Fact Document、lifecycle、provenance、因果边、校正裁决住在 tenant SQLite。投影 outbox 也是 SQLite 状态，不是 Web PostgreSQL。

P5

OpenViking 是可替换索引

Fact Index 只有 apply / search / reset。Managed Causal Projection 用确定性 Task 或 Channel/month 分区。L0/L1 是导航，不是证据。

P6

双 Citation

OpenViking Citation 证明读到了哪个 URI/version。Causal Memory Citation 证明 admitted 因果证据。前者不能驱动校正。

P7

失败降级，不挡群聊

OpenViking 故障时因果 candidate 走本地 SQLite；identifier-based trace / intervene 继续走图。切换保留数据；删除 Workspace 才做可重试清理。

明确拒绝：自然语言 intent Router；把 OpenViking 摘要静默回填成因果事实；让 L0 参加 intervene；把目录父子当成 caused；把 viking:// 当成 canonical identity；修改默认 Compose / release / staging / production。

3.3 · 目标架构

一个 profile，一条内部管道，没有路由器

Workspace 先选定 profile。完整 OpenViking 始终走 deny-by-default gateway。因果 profile 里，admitted 段进入 Causal Memory；active Fact Document 经 outbox 投影到 Managed Causal Projection；检索先 Fact Index 再 Hippocampus。没有按自然语言选择树或图的门面。

3.7 · 落地顺序

按实施计划的 tracer-bullet，不按旧 P0–P3

顺序来自 openviking-causal-memory-profiles-plan.md。本页不发明另一套阶段名。

阶段做什么验收不做什么
D 文档与盘点 更新 architecture / Web module map；重写本走查；pin OpenViking 接口清单。 规范不再把 CM 写成唯一 profile；本页标明 non-normative。 不改默认 Compose；不改 OV 源码。
C 合同冻结 profile / gateway / Agent citation 预算 / Fact Index 合同先红后绿，再 C4 冻结。 未知路由拒绝；OV citation 不能校正；Fact Index 只有三操作。 不在合同阶段写 Prisma 或真实 HTTP。
P+G 调和与网关 profile 状态机、一次 schema、gateway tracer，再铺完整路由目录。 一条授权读写穿过 gateway；身份 header 被剥离。 不把管理面放进 generic proxy。
O+V+R 投影与检索 SQLite outbox、本地 fallback、OV Fact Index 适配器、watermark + delta。 read-your-writes；stale 拒绝；OV 故障不挡 Message。 不把 LanceDB 接到新的 CoForge 缝。

两个 profile 都保留的

  • 完整 OpenViking backend（经 gateway）
  • 同一条 PublicChannel admission 规则
  • Memory Agent 只读围栏
  • 失败不阻塞普通群聊

不要做的

  • 按问句选择 CM 或 OV 真源
  • 同一 admitted 段双写两套抽取器
  • 用 OV URI 充当因果 provenance
  • 把 prototype 放进默认 Compose / release
